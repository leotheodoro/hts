# Autenticação · plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Contas com login por username ou e-mail, sessão persistente no iPhone, API fechada por conta e programas do treinador servidos só para a conta.

**Architecture:** A API ganha `account` e `auth_session` (só no servidor), rotas `/v1/auth/*` e um middleware que resolve o token na conta e no `athleteId`; sync e atletas passam a ser restritos ao atleta da sessão. Um seed TS cria a conta e importa o plano do treinador, de um JSON fora do git, com a notação portada do Swift e fixtures compartilhados. O app guarda a sessão no Keychain, abre no login sem sessão e deixa de trazer o plano no bundle.

**Tech Stack:** Hono + @hono/zod-openapi, Drizzle/postgres-js, Vitest, `@node-rs/argon2`; Swift 6, SwiftUI, GRDB, swift-openapi-generator, Security (Keychain).

**Spec:** `docs/superpowers/specs/2026-10-30-auth-design.md`

## Global Constraints

- Nada de senha, hash ou token em arquivo commitado; o repositório é público. Segredos só em `.env` (fora do git) e no Render.
- `SEED_NAME=Leonardo Theodoro`, `SEED_USERNAME=leotheodoro`, `SEED_EMAIL=simplespinheiro@gmail.com`; `SEED_PASSWORD` só no `apps/api/.env`.
- Hash de senha: argon2id (`@node-rs/argon2`). Token: 32 bytes aleatórios, base64url; o banco guarda só o SHA-256 (hex).
- Sessão sem expiração; vale até `revoked_at`.
- Login: identificador sem diferenciar maiúsculas e com espaços aparados; resposta de erro idêntica para usuário inexistente e senha errada (`401 { error: "invalid_credentials" }`).
- Limite: 10 tentativas de login por 15 min, por IP e por identificador, em memória; `429 { error: "too_many_attempts" }`.
- Copy pt-BR (String Catalog): "Entrar", "USERNAME OU E-MAIL", "SENHA", "Usuário ou senha incorretos.", "Sem conexão. O login precisa de internet.", "Muitas tentativas. Tente de novo em alguns minutos.", "Sair". Sem exclamação, sem emoji.
- Visual só com tokens (`Color.hts.*`, `Font.hts`, `HTSSpacing`, `HTSNotch`); `blood` só no SUBMIT e no botão Entrar.
- Fluxo do repo: um ticket por tarefa (issue em `leotheodoro/hts`, branch `<N>-slug`, PR com `Closes #N`, `make ios-test` local, squash merge com CI verde, card no quadro), gitmoji, sem linha de co-autor de IA.
- Depois de mudar schema, rotas ou fixtures: `pnpm --filter api contracts:generate && pnpm sync:shared` e commitar.
- Apagar o banco do Render só com o ok do Leo na hora.

## Review Focus

- Login com o e-mail em maiúsculas ou com espaço no fim deve entrar (Task 2 testa `"  SimplesPinheiro@Gmail.com "`).
- Push de sync com uma linha de outro atleta, ou com o `id` de uma linha que já pertence a outro atleta, não pode gravar nada (Task 3 testa os dois).
- App aberto offline com sessão salva deve ir direto à Home, sem tentar login (Task 7 testa `start()` com o cliente falhando).
- Reinstalar o app (sem a marca no `UserDefaults`) deve apagar a sessão do Keychain e abrir o login (Task 7 testa o reset).
- Um 401 na sync (sessão revogada) deve voltar ao login sem apagar o SQLite (Task 7 testa).
